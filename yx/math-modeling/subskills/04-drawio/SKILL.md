# 论文级非数据图示绘制

本 skill 承接 `03-coding`，负责论文中的**非数据型图示**：技术路线图、求解流程图、模型结构图、变量关系图、几何机制示意图、指标体系图等。

本阶段的目标不是“生成一个能导出的图片”，而是生成一张：

- 能回答一个明确论证问题；
- 读者在缩小到论文版心后仍然看得清；
- 几何关系、箭头语义和文字层级正确；
- 有可复现源文件；
- 经过渲染预览、多轮视觉检查和红队复审的论文级成品图。

**单遍交付不等于一次生成。** `05-writing` 只引用本阶段最终成品，但本阶段必须在交付前完成内部的“设计 → 渲染 → 检查 → 修改”迭代。

## 阶段边界

- 本阶段负责：非数据图的结构设计、工具选择、源文件、PNG/PDF、图示自检和生成记录。
- 本阶段不负责：折线图、柱状图、散点图、热力图、箱线图、雷达图等数据图；这些由 `03-coding` 生成。
- 本阶段不重跑模型、不修改 `code/`，不改写 `RESULTS_REPORT.md` 中的数值结论。
- 图示中的数值、术语和模型关系必须来自前序报告或题面，不得为了视觉效果编造内容。

## 工具选择：不要强制所有图都用 DrawIO

先根据图的语义选择工具，再决定是否调用 `scibox-diagram`：

| 图示类型 | 首选工具 | 交付源文件 |
| --- | --- | --- |
| 技术路线图、研究框架图、任务分解图 | DrawIO 模板 | `.drawio` |
| 子问题求解流程、数据 Pipeline、决策树 | DrawIO | `.drawio` |
| 模块关系、系统架构、指标体系 | DrawIO 或 TikZ | 对应源文件 |
| 精确二维几何、公式节点、变量关系、遮蔽判据 | TikZ/LaTeX 优先 | `.tex` |
| 复杂物理场景、需要自定义矢量图元的示意图 | SVG、TikZ 或 Matplotlib | 对应源文件 |

规则：

1. **流程和模块关系**优先使用 DrawIO，因为可编辑连接器和模板更有优势。
2. **公式密集、几何精确或需要数学标注的图**不要为了满足“DrawIO”名称而硬画，优先 TikZ/LaTeX。
3. 若采用 TikZ/SVG，仍由本阶段负责 PNG/PDF 导出、视觉验收和 `DRAWIO_REPORT.md` 记录；不必伪造一个没有实际用途的 `.drawio`。
4. 若用户或项目明确要求可编辑 DrawIO，则优先满足该要求；几何图可同时保留 TikZ 作为排版源。

## 必须产出

在当前项目中创建或更新：

```text
figures/
  fig_*.png                         # 论文引用成品
  fig_*.pdf                         # 条件允许时保留矢量 PDF
  fig_*.drawio / fig_*.tex / ...    # 与工具对应的可复现源文件
  fig_*.visual-spec.md              # 自定义图的视觉规格
  fig_*.layout-grid.md              # 自定义图的栅格与坐标计划
  fig_*.defect-log.md               # 迭代缺陷记录
reports/
  DRAWIO_REPORT.md                  # 本阶段生成与验收报告
```

模板图可以用模板的 `content.json` 代替重复的坐标计划；复杂自定义图必须保留 `visual-spec.md`、`layout-grid.md` 和 `defect-log.md`。如果某个文件确实不适用，在报告中说明原因。

每张图至少应有：

- 一个明确的论文用途和图题建议；
- 一个唯一的源文件；
- 一张最终 PNG；
- 前序报告依据；
- 视觉检查和语义核对记录。

## 工作流程

### Step 1：盘点前序材料并确定图的论证任务

先读取以下文件（存在则读取）：

- `reports/ANALYSIS_MODELING_REPORT.md`
- `reports/RESULTS_REPORT.md`
- `figures/` 目录列表
- 论文草稿中已有的图题和图引用

为每张候选图写出一句话：

> 这张图要帮助读者看懂什么？

如果一句话说不清，先删减或合并图示，不要直接开始画。

然后输出清单：

```text
FIGURE PLAN CHECKLIST:
[ ] fig_roadmap      技术路线图，展示整体解题路线
[ ] fig_flow_q1      问题一求解流程图
[ ] fig_flow_q2      问题二求解流程图
[ ] fig_pipeline     数据处理流程图
[ ] fig_model        模型结构/几何机制图
```

清单不是固定模板，应根据题目实际删减；不要为了凑数量生成重复或无论证作用的图。

### Step 2：判定图型、工具和信息结构

常见图示选择：

| 图型 | 适用内容 |
| --- | --- |
| 技术路线图 | 题目、数据、模型、算法、结果之间的整体关系 |
| 求解流程图 | 输入、判断、算法、输出、反馈和停止条件 |
| 模型结构图 | 模块、变量、输入输出和依赖关系 |
| 几何机制图 | 空间关系、对象形状、距离、截面和判据 |
| 指标体系图 | 目标层、准则层、指标层及其归属 |

设计时先区分四类元素，不要全部画成同一种盒子：

- **实体/对象**：使用实际几何形状或图标；
- **关系/运动**：使用有明确方向的实线或虚线；
- **公式/判据**：使用独立公式区域或公式节点；
- **解释/备注**：使用短注释，不把整段论文正文塞进图中。

#### 几何模型图的推荐结构

对于遮蔽、碰撞、投影、力学等几何模型，优先采用：

```text
主场景：对象、运动方向、视线/轨迹、核心几何关系
        ↓
局部放大图：截面、垂距、半径、角度或判据
        ↓
简短公式：核心不等式或目标函数
```

不要用一个大圆、几条线和多段文字同时承担主场景与公式推导。必须明确投影平面；目标、球体、圆柱等有尺寸实体应尽量画出实际形状，而不是只放一个文字框。

### Step 3：建立视觉规格和栅格计划

在写 XML 或绘图代码前，创建：

- `fig_<id>.visual-spec.md`：记录图的目的、视觉层级、颜色、字体、对象清单和每条连线的语义；
- `fig_<id>.layout-grid.md`：记录画布尺寸、页边距、列基线、主场景/插图区域、重复元素尺寸、步距和绘制顺序。

至少回答：

1. 画布最终以多大的论文物理尺寸出现？
2. 主阅读方向是什么？读者先看哪里，再看哪里？
3. 哪些元素属于同一族，如何保持对齐和同宽？
4. 每根箭头从谁指向谁，表达运动、推导、输入还是输出？
5. 哪些内容应放入局部放大图，而不是挤在主场景？

版式硬约束：

- 内容主体尽量占画布的约 65%～90%；若明显低于此范围，必须说明留白的论证用途。
- 标题默认交给论文 caption；若图内保留标题，必须横向居中并覆盖完整标题区域，不能只占画布一侧。
- 全图尽量收敛到 2～3 种字号，正文和标注不能小到缩印后不可读。
- 颜色按语义分配，通常控制在 4～6 个主色；同语义同色，灰度下仍能区分。
- 同一类连接器使用同一线宽、箭头和虚实规则。

DrawIO 手写图还必须读取并遵循：

- `scibox-diagram/references/authoring.md`
- `scibox-diagram/references/self-check.md`
- `scibox-diagram/references/preflight-rules.md`

### Step 4：按工具路线绘制

#### 4A. DrawIO 路线

模板适用时使用：

- `roadmap-5band`
- `framework-3col`
- `stageflow-3col`
- `taskflow-land`

模板不适用时，从零手写 XML，但必须先完成 Step 3 的栅格计划。DrawIO 手写图的基本要求：

- 使用稳定、可读的 cell id；
- 中文手动断行；
- 几何直线使用直线连接器，不用正交连接器强行表达斜线；
- 边上标签过长时改成独立文字 cell；
- 公式、判据和备注与实体对象分层；
- 连接器端点离盒边留出空间；
- 背景底色块不应遮挡实体或参与碰撞检查。

渲染、校验与导出（Windows 下使用 `python`）：

```bash
python scibox-diagram/scripts/check_layout.py figures/fig_x.drawio --strict
python scibox-diagram/scripts/export_figure.py figures/fig_x.drawio
python scibox-diagram/scripts/preview_html.py figures/fig_x.drawio
```

`check_layout.py` 是结构门禁，不是美观门禁；通过后仍必须打开 PNG 检查。

#### 4B. TikZ/LaTeX 路线

适用于精确二维几何、公式密集或变量关系复杂的图。要求：

- 源文件中的几何坐标、公式和标签可追溯；
- 使用统一字体、线宽和颜色；
- 先编译 PDF，再按论文实际尺寸导出 PNG；
- 通过编译日志、PDF 页面边界和最终 PNG 检查文字裁切与字体大小。

#### 4C. SVG/Matplotlib 路线

仅用于复杂场景或需要自定义矢量图元的非数据示意图。不得把数据图伪装成示意图；所有对象、标注和颜色仍须有明确语义，并保留生成脚本和参数。

### Step 5：结构门禁与渲染检查

#### 5.1 机器检查

DrawIO 图必须：

- XML 可解析；
- `check_layout.py --strict` 为 `FAIL 0 / WARN 0`；
- 没有嵌入 PNG/JPEG 位图（除非在报告中明确说明）；
- 没有重复 id、文字溢出、越界、盒子重叠和连线穿盒。

TikZ/SVG/Matplotlib 图必须完成对应的编译、导出和文件存在性检查。

#### 5.2 论文尺寸检查

不能只看放大后的画布。必须同时检查：

1. 全画布：整体重心、留白、阅读路径；
2. 论文实际版心尺寸：文字、公式、箭头是否仍然可读；
3. 缩略图：3～5 秒内能否识别图的主题和主关系；
4. 灰度或低饱和度预览：颜色是否仍能区分语义；
5. 局部放大：标签是否压线、压形状或与公式重叠。

“导出 2 倍 PNG”不自动等于“300 DPI”。应根据论文最终物理尺寸确定像素宽度，并在报告中记录导出尺寸和方式。

### Step 6：多轮视觉复审

自定义示意图至少完成 **2 轮**“渲染 → 逐区检查 → 修改 → 重渲”；高保真复刻至少完成 3 轮。

每一轮必须在 `fig_<id>.defect-log.md` 中记录，并按九区检查：

| 区域 | 检查内容 |
| --- | --- |
| 文字 | 溢出、压线、断行、缩印可读性 |
| 箭头 | 方向、起止、虚实、扇入扇出语义 |
| 盒子/图形 | 重叠、比例、同族对齐、实体形状是否准确 |
| 间距 | 族内步距、族间留白、主次区域关系 |
| 配色 | 同语义同色、颜色数量、灰度可辨识性 |
| 字体层级 | 字号数量、粗细、公式与正文层级 |
| 版面 | 重心、留白、阅读路径、画布利用率 |
| 图标/符号 | 一致性、尺寸、近似是否说明 |
| 整体风格 | 是否像一张完整图，而非多个局部拼接 |

最后增加一次红队复审：假设自己是不了解绘图过程的评审，只检查图能否正确读懂，不接受“坐标上看起来合理”作为依据。

交付前自评分卡满分 50 分：

- 文字可读性 /10
- 箭头准确性 /10
- 配色一致性 /10
- 版面一致性 /10
- 风格与论文匹配度 /10

总分低于 45，或任一项低于 5，不得交付；必须继续修改并记录原因。

```markdown
- 字体与字号：
- 配色语义：
- 主场景/插图结构：

## 导出与机器检查
- 命令：
- 输出尺寸：
- check_layout/编译结果：

## 视觉复审
- 迭代轮数：
- 九区检查：
- 红队复审：
- 自评分数：
- 遗留问题：

## 给论文阶段的嵌入建议
```

生成源必须唯一且可复现：

- 如果由 Python 生成 XML，生成脚本或 content JSON 是源文件；不要只手改最终 `.drawio`。
- 修改 `.drawio` 后，必须同步生成脚本或记录为新的源版本。
- 脚本的输出路径应基于脚本位置解析，不依赖当前 shell 工作目录。
- 报告中记录实际生成命令、工具版本和最终源文件。

嵌入建议只说明章节和 caption，不在本阶段写论文正文。`05-writing` 只引用通过本阶段验收的最终 PNG/PDF。

## 质量底线

- 图服务于论文论证，不为装饰或凑数量而画。
- 每张图都能回溯到 `ANALYSIS_MODELING_REPORT.md` 的真实方法或题面条件。
- 数据型图不在本阶段重复生成。
- 几何图必须展示实际几何关系，不能只用一组说明框替代模型。
- 任何“FAIL 0 / WARN 0”都不能替代人工视觉检查。
- 发现硬错误时，先修源文件并重新渲染；不得只在报告中解释而保留错误成品。
